# 安全說明：擋得住什麼、擋不住什麼

Xing Janus 會在你的電腦上讀檔、改檔、跑指令。它的守門層叫 Cerberus，有三個頭：

| | 做什麼 |
|---|---|
| 權限規則 | 每個動作決定：直接做、問你、或拒絕。機密檔（`.env`、私鑰、`credentials`…）讀寫都擋；危險指令每次都問 |
| OS 沙盒 | 指令只能讀工作目錄、加進來的資料夾（和你允許的工具鏈），只能寫工作目錄、也能改的資料夾和暫存目錄，網路預設全擋、碰到新的網域問你。xj 自己讀檔、改檔、搜尋的工具也只到同一個範圍 |
| 信任的資料夾 | 別人的 repo 裡會被執行的東西（`package.json` 的 scripts、git hooks）只在你信任的資料夾才會直接跑；加成也能改的資料夾也要信任過 |

**白名單只是讓你少被問幾次，安全邊界是沙盒。** 沙盒啟動不了時，一律拒絕跑指令。
沙盒和模式是分開的兩個設定：沙盒管碰得到哪裡，模式只管要不要先問你，換模式（包括全部不問）不會開關沙盒。設定檔放寬了哪些（關掉沙盒、允許切到全自動、全部不問…），`xj doctor` 的「設定檔放寬的」那一列會列出來。
沙盒開著、關掉時每個模式會怎樣，見 [usage.md](usage.md) 的「沙盒和模式」（完整的表只放在那裡）；你的情況該怎麼設，見 [setup-guide.md](setup-guide.md)。
抓網頁（`web_fetch`）是 xj 自己連線、不經過沙盒，但用的是同一份網域清單，連線前的位址檢查也是沙盒程式庫的那一套。

## 擋不住、要你自己注意的

- **工作目錄裡的東西**：沙盒允許改工作目錄（和你加成也能改的資料夾），所以 `rm -rf`、`git reset --hard` 擋不住（它們在危險清單上，會先問你；全部不問模式不問）。改動請用 git 管理。
  機密檔也一樣：沙盒裡的指令讀不到，但間接改得到（例如 `npm test` 跑的程式往 `.env` 加一行）；xj 自己的工具和寫出檔名的指令才擋得住寫。
- **加成也能改的資料夾（`/add-dir`、`--add-dir`、`permissions.addDirs`）**：跟工作目錄同一套規矩，沙盒裡的指令也寫得到，所以上一條也適用。
  要在電腦前面信任過（那裡的 `package.json` 的 scripts、git hooks 之後會被執行）；機密檔、受保護的檔案（那個資料夾自己的 `.git/hooks`、`.vscode/tasks.json`…）照樣擋。
  家目錄、它的上層、根目錄、放憑證的資料夾、`~/.xing-janus` 加不進來；放著 xj 在沙盒外跑的程式（git、rg…）、PATH 上的資料夾、xj 自己的程式的，只能加成只能讀的
  （沙盒裡的指令換得掉那些程式，之後就在沙盒外以你的權限跑）。只加你要改的那幾個：加的是工作目錄的上層的話，裡面所有的專案都在範圍裡（見 usage.md 的「加進來的資料夾」）。
- **機密檔照檔名認**：清單在 config.md 的「內建的白名單、危險清單、機密檔」。別的名字的金鑰（例如 `deploy_key`、`service-account.json`）擋不到，請加進 `permissions.secretFiles`。
- **提示注入**：檔案、網頁裡可能藏著要 AI 做壞事的指令。它被教成把讀到的東西當資料，不當指令，但不保證。只在你信任的程式碼裡用。
- **模型提議改設定**：模型寫不了 xj 的設定檔，只能提議（`settings_propose`）：每一項標放寬、收緊或不影響權限，你答應了 xj 才寫（放寬的標紅、要按 `y`）。讀到的檔案、網頁可能叫它提議放寬（提示注入）：
  標紅的那幾項看清楚是不是你要的。不信任的資料夾裡 xj 不收放寬的提議；全部不問、拿掉內建的保護、MCP server、金鑰這類模型不能提（usage.md 的「改設定」）。
- **抓網頁（`web_fetch`）**：網頁的內容是任何人都能寫的，是最常見的提示注入來源；網址本身也能把資料帶出去（查詢字串裡放檔案的內容）。
  所以每個新網域都問你、問的時候整個網址看得到，網址裡像金鑰的一定問。**允許過的網域，之後的網址就不會再給你看**：
  只對信得過的網站（官方文件、套件的網站）按「這次對話都允許」或「永久允許」；不認識的、誰都能架的網站（個人網域、免費的託管空間）按「允許一次」：
  那種網站的主人看得到每個網址。
  抓網頁的是 xj 自己，不在沙盒裡；本機、雲端的 metadata 位址它自己擋（見 usage.md 的「抓網頁」）。
- **子代理**：子代理的每個動作照樣經過 Cerberus，找東西的（explore）由 Cerberus 擋成唯讀，不是只靠提示。
  但它讀到的檔案、網頁裡藏的指令，可能混進它交回來的報告：報告對主代理來說是資料（不是你說的話），被交代重要的事要自己再確認。
  會改檔的（general）做完，xj 會把實際改了哪些檔列給主代理（不靠子代理自己講）；改檔照你的模式問你，答應的一定是你。
- **追蹤在 git 裡的機密檔**：`git diff`、`git log -p` 會印出內容。機密檔不要放進 git。
- **鑰匙圈**：沙盒裡讀不到鑰匙圈的項目（2026-10-17 在 macOS 15 上實測）。`security` 本來也在危險清單上，會先問你。
- **關掉沙盒（`--no-sandbox`、設定檔的 `sandbox.enabled: false`、`/sandbox off`）、MCP server 的 `sandbox: false`、`sandbox.excludedCommands`**：這些都會讓程式以你的權限在沙盒外跑
  （`excludedCommands` 列的指令每次都問，全部不問模式不問；見 config.md 的「Docker」）。關得了沙盒的只有你：設定檔、指令列、你打的 `/sandbox`
  （模型只能提議改設定檔，你答應了才寫；專案資料夾裡的檔案關不了）。沒有沙盒的時候，xj 自己的讀檔、改檔工具也碰得到工作目錄以外：
  範圍外的每個都問（全部不問除外）；機密檔、放憑證的地方、xj 自己的資料夾照樣擋，改的話另外擋受保護的檔案、之後會自動執行的地方（shell 的啟動檔、開機自動跑的服務、排程…）（見 usage.md 的「沙盒」）。
- **全自動模式（`--auto`、設定檔的 `allowFullAuto`）**：沙盒開著時拿掉了「每個指令都看一眼」這一關，只剩沙盒和危險清單（沒有沙盒時指令照樣每個都問，只有改檔不問）。
  工作目錄裡的改動、你之後在沙盒外跑的原始碼，都要你自己用 git 看過（見 usage.md 的「全自動模式」）。
- **全部不問模式（`--dangerously-skip-permissions`、設定檔的 `allowBypass`）**：不問你（每次開 xj 第一次進去要打字確認）。它只換模式、不動沙盒：
  沙盒開著的話指令照樣關在沙盒裡、網路只到允許的網域（沒允許過的不問就擋），但工作目錄裡的刪改、push 到允許過的網域擋不住；
  沒有沙盒的話三個頭只剩權限規則的一小部分（名字原樣寫在指令裡的機密檔、受保護的檔案：換一種引號、用大括號列出來、寫在 `bash -c '…'`、`eval '…'`、`$( )` 裡面的、交給 `cmd`、PowerShell 的字串裡的（`cmd //c "type .env"`）也算），指令以你的權限在你的電腦上跑，
  要算出來的名字擋不到：`grep -r`、`cat *`、變數、別的程式的程式碼（`node -e`、`python -c`）、用管線餵給 shell 的字串（`echo 'cat .env' | sh`）這類讀法讀得到 `.env`：只在可以整個丟掉的容器、虛擬機裡用。
  兩種都照樣問：切換成 root、刪掉重要的地方（根目錄、根目錄下第一層、家目錄、工作目錄和它的上層、加進來的資料夾；設定檔的 `permissions.bypassAsksCriticalDelete` 關得掉）、
  你自己加進 `permissions.danger` 的、xj 看不完的指令（一層包一層包得太深、大括號展開出太多字：沒檢查到的不當成沒事）。這些照指令的字認，寫成程式去刪的認不出來（見 usage.md 的「全部不問模式」）。
- **共用的 Gradle、pub 快取**：Flutter／Android 的 build 要能寫 `~/.gradle`、`~/.pub-cache`，所以沙盒裡寫得到。
  會自動執行的位置（init 腳本、`wrapper/dists`、`pub-cache/bin`）有另外擋，但快取裡的 jar 和套件原始碼還是可以被改，下次你自己 build 時會跑到。
  很在意的話，在設定檔把 `sandbox.writable` 清空，並讓每個專案用自己的 `GRADLE_USER_HOME`、`PUB_CACHE`。
- **npm 的快取**：家目錄在沙盒裡是擋掉的，所以沙盒裡的 npm 不會用你機器共用的 `~/.npm`，而是用 `~/.xing-janus-cache/npm`（Xing Janus 自己的）。
  意思是：第一次裝套件會重新下載一次，而且沙盒裡的程式改不到你自己在用的快取。`~/.npmrc` 讀不到（裡面可能有 token），
  所以要私有 registry 的專案，設定要放在專案自己的 `.npmrc`。
- **在家目錄開不起來**：工作目錄是家目錄、家目錄的上層或 `/` 時，Xing Janus 會拒絕啟動（那等於把整個家目錄交出去）。請 cd 到專案資料夾。
- **Windows**（2026-10-20，沙盒是 alpha）：沒裝沙盒的時候每個指令都會問你（白名單不生效）。PowerShell 的白名單只認很單純的寫法
  （2026-10-21）：`Get-ChildItem`、`Get-Content`、`Select-String` 這類唯讀的 cmdlet，參數都是字面上的值（沒有 `$` 變數、括號、雙引號、
  重新導向），路徑在專案裡（或你另外開放讀的資料夾裡）。`Select-String` 前面接 `Get-ChildItem`、`Get-Item` 的不算（它會打開那些檔案來搜）。
  其他的寫法 xj 看不出它實際會跑什麼，一律要問，全自動模式也問。
  沙盒用另一個帳號跑，你的家目錄它本來就讀不到；但還不存在的受保護檔案擋不到建立（xj 會提醒），其他限制見 troubleshooting.md 的「Windows」。
- **Windows：「所有登入的帳號都改得了」的資料夾**（2026-10-27 實測）：沙盒擋寫靠的是沙盒帳號自己的權限，所以**不是**你的東西沙盒就一定改不到 ——
  非系統磁碟的根目錄（`D:\` 預設就是所有登入的帳號可以修改）、`C:\` 底下你自己建的資料夾（`C:\tools` 這種，從 `C:\` 繼承）沙盒裡都寫得進去。
  xj 開沙盒時會實際試寫一次：**沙盒外會被執行的地方寫得進去的話，白名單就不生效、每個指令都先問你**（畫面和 `xj doctor` 會列出是哪幾個、怎麼用 `icacls` 擋）。
  試寫的是：PATH 上的資料夾、沙盒讀得到的工具鏈的根目錄（例如 `C:\src\flutter`）、Git Bash 自己的資料夾、`excludedCommands` 的程式所在和它的 SDK。
  磁碟根目錄寫得進去只講一聲（那是 Windows 的預設），意思是沙盒裡的程式改得到你放在那顆磁碟根目錄底下的**別的專案**。
  很在意的話：把工具裝在 `Program Files`（一般使用者改不了），或用系統管理員權限替那幾個資料夾加一條擋沙盒帳號的權限。
  警告裡印的 `icacls` 指的是**往上連續寫得進去的最上層**（例如 `C:\src`，不是只有 `bin`）：擋在那裡，底下整個工具鏈跟著擋；
  只擋 `bin` 的話沙盒裡的指令照樣改得到工具鏈其他的部分，之後在沙盒外跑它（`excludedCommands`，或你自己在 xj 外面跑）時，執行的就是被改過的程式。
  它不會叫你擋家目錄、專案或它們的上層（那會連 xj 要寫的地方一起擋）。
  **放在那些地方、會在沙盒外跑的程式**（xj 自己的 git、跑沙盒外指令的 Git Bash、`excludedCommands`、flutter 這類沙盒裡跑不了的工具、MCP server、搜尋用的 rg）
  沙盒裡的指令換得掉，之後 xj 在沙盒外用你的權限跑的就是換過的那一支：開沙盒時問你一次這次對話要不要照樣在沙盒外跑（選「否」的話它們不跑，搜尋改在沙盒裡跑），
  之後要你核准才跑的指令照樣每次問、標紅。設定檔的 `sandbox.writablePrograms` 可以改成不問就不跑（`"deny"`）或不問照樣跑（`"allow"`），見 config.md。
- **Windows：開著沙盒的時候，不要同時在不可信的專案裡開另一個 xj**：所有 xj 的沙盒都用同一個 `srt-sandbox` 帳號；
  這個 xj 開著的時候，它開放給沙盒的權限（例如可寫的專案資料夾、工具鏈），另一個 xj 的沙盒裡的指令也拿得到，直到這個 xj 結束、權限收回。
  機密檔照樣擋得住：xj 開沙盒時先擋機密檔，才開放資料夾。有幾個很短的時刻例外：機密檔被換成另一個檔案、xj 重新擋的那一下（先整批放掉再擋回去），
  另一個 xj 的沙盒裡剛好在跑的指令讀得到機密檔、改得到受保護的檔案。
  受保護的檔案所在的資料夾（例如 `.git`）的「不能刪除」是沙盒的帳號和群組各一條、開放資料夾之前就加：srt-win 改權限時（另一個 xj 做的也算）會拿掉帳號那一條，
  群組那一條它不碰，所以專案裡面那幾層另一個 xj 的沙盒也改不了名；工作目錄本身 xj 開著的時候誰都改不了名。
  例外是也能改的 `/add-dir` 資料夾本身：另一個 xj 動到它（重新準備、關掉沙盒）之後，到這個 xj 下一次重新擋之前擋不住它改名
  （而且要它的上一層是誰都建得了資料夾的地方才改得了，例如 `C:\` 底下自己建的資料夾、資料磁碟）。
  這個 xj 自己放到背景的指令不會：它們還在跑的話 xj 先不重新擋，叫你先停掉（troubleshooting.md 的「Windows 的沙盒跟 macOS、Linux 不一樣的地方」）。
- **`flutter`、`dart`（和 `fvm`）不能在沙盒裡跑**（每個平台都一樣）：它們每次執行都要寫 Flutter SDK 自己的 `bin/cache`，沙盒裡寫不進去。
  例如 Windows 上（2026-10-27 實測）它們的 `.bat` 要寫 `bin\cache`（鎖檔、各種 `.stamp`），
  SDK 在沙盒裡是唯讀的，`flutter.bat` 會卡住不動。xj 不讓它卡住：模型會要求在沙盒外跑那一個指令，每次都問你（config.md「沙盒裡跑不了的工具」）。
  開放整個 `bin\cache` 可寫不是辦法：那裡面的 `dart.exe`、snapshot、artifacts 之後都會在沙盒外以你的權限執行。
- **自己脫離的背景程序**：xj 結束時（包括被強制結束），會把它開的指令（包括放到背景跑的，`/jobs`）、MCP server 整組收掉。但指令自己脫離出去的程序（用了 `setsid`、`set -m`，或會自己轉成常駐程式的服務）收不到。在 Linux 的沙盒裡，它們會跟著指令一起結束；在 macOS 上會留下來，要自己用 `ps` 找出來結束。
  Windows 比較嚴（2026-10-22 實測）：指令開的每個程式都在同一個 job object 裡、脫離不了，**指令一結束就全部收掉**，
  包括視窗程式（`start` 開的也一樣）和 Gradle daemon 這種常駐程式；開著沙盒時也一樣（沙盒自己的 job object）。
  例外是沒開沙盒、用 Microsoft Store 裝的 PowerShell 7 時（2026-11-05 實測）：Store 的程式自己在 Windows 給的 job object 裡，那個 job 准許子程序脫離，
  所以它開的程式不在 xj 的 job object 裡。Ctrl-C、逾時時 xj 照父程序收（還在跑的 PowerShell 和它開的程式），指令結束之後留下的、父程序已經結束的程式收不到（跟 macOS 一樣）。
  要一律收乾淨的話，PowerShell 7 請裝官方的 MSI（裝到 Program Files）。
  xj 結束之後還要留著用的程式（開發伺服器、模擬器、編輯器）請在 xj 外面自己開（開著 xj 的時候要用的開發伺服器，可以叫模型放到背景跑）；已經開著的程式（例如指令只是叫瀏覽器開一個新分頁）不受影響。

回報安全問題的方式見 [SECURITY.md](SECURITY.md)。
